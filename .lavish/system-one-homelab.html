Recommendation

Use System One as a decision gate, not as an infra pilot

Best first fit: enrich and route existing Gotify/systemd alerts with a typed local classifier. Start in shadow mode. Let it explain and prioritize; do not let it edit firewall, WireGuard, secrets, or storage.

1. Keep hard checks hard

Existing scripts like public-check.sh, backup-watchdog.sh, and make check should still fail deterministically.

2. Classify the messy part

Use the model only where logs, timers, process state, and error text need interpretation.

3. Gate with thresholds

high confidence = annotate/downgrade safe noise; low confidence = page human. Auto-mutation comes later, if ever.

Minimal architecture

One local service, one policy gate, one audit trail. No new platform.

localhost-only

Small implementation path

  • Create localhost-only decisiond
  • Add homelab-notify wrapper for notify@
  • Shadow mode: log decisions, do not suppress
  • Enable one safe action: media quarantine or notification priority
  • Review audit logs before any auto-remediation

Policy shape

if confidence >= 0.95 and label in safe_noise:
  downgrade_or_hold_notification()
elif confidence < 0.80 or label == "unknown":
  page_human_now()
else:
  notify_with_label_and_score()

Use allowlists per unit/service. A model score alone should never authorize destructive work.

Do not use it for these

Editing /etc/wireguard or nftables
Deleting media, backups, or stack state
Changing Tailscale/VPS access paths
Declaring backups valid when hard checks fail
